Guest user (Windows)

The user is created + set to autologon in the Windows golden when the Windows prep command (Images page) runs in the VM. Changes here only apply to goldens prepared afterwards (run prep again → upload). Linux golden: the user already exists in the image.

SSD room (Windows machines)

GB
GB
GB

Everything a guest writes (C:, games drives) lands on the machine's SSD until the next boot. At each boot the stage frees Keep free GB (parked images, unused the longest first). During the session a watchdog checks the SSD every 15 s: below Warn it tells the guest (and the Machines page shows SSD full); below Restart it restarts the machine after 60 s — otherwise Windows would crash with a blue screen once the SSD is full. Big writes come mostly from launchers updating games on the machines: let only the games disk's update machine update them. Applies at each machine's next boot.

RAM cache — RAM reserved for the server

MB

Loading a golden into the RAM cache (compressed copy: Linux = the iSCSI target serves it, Windows = golden.vhdx downloads come from it, the disk is never read) claims its RAM before loading: the golden's data (holes not counted) at its worst-case compressed size. Refused if that + reserve > available RAM → never runs out halfway; what compression saves is given back once loaded. Reserve = RAM kept for the OS + serving. Not enough → the image falls back to disk by itself.
