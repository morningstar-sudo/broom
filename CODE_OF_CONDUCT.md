# Code of Conduct

Broom is built and used by people who run labs, internet cafés and classrooms — often alone, often under time
pressure when a room of machines won't boot. This document says how we treat each other in the project's spaces, so
that asking for help, reporting a bug or sending a fix is something anyone can do without hesitation.

## Our pledge

We, as contributors and maintainers, pledge to make taking part in this project a harassment-free experience for
everyone, whatever their age, body, disability, ethnicity, sex characteristics, gender identity and expression, level
of experience, education, social or economic status, nationality, appearance, race, religion, sexual identity or
orientation, and whatever language they write in.

## Expected behaviour

- **Be kind and patient.** Many users are not developers; a question that seems basic to you may come after hours of
  trying. Answer the question that was asked, or point to where the answer is.
- **Write so others can follow.** Vietnamese and English are both welcome. If you can, add a short summary in the
  other language for a long post — not required.
- **Assume good faith.** A blunt bug report usually means a broken room, not a personal attack.
- **Criticise code and decisions, not people.** Explain *why* something is wrong and, where you can, what would be
  better.
- **Accept that maintainers decide.** Not every feature fits; a "no" with a reason is a normal outcome, not an insult.
- **Give credit.** Say where code, ideas or text came from, and respect their licences (Broom is Apache-2.0; the
  embedded iPXE is GPLv2 with the UBDL exception — see the README).

## Unacceptable behaviour

- Harassment, insults, threats, or sexualised language and images.
- Personal or political attacks, trolling, and deliberately derailing discussions.
- Publishing someone else's private information (address, phone number, real name behind a handle) without their
  explicit permission.
- Sustained disruption of issues, pull requests or discussions.
- Any other conduct a reasonable person would find inappropriate in a professional setting.

### Specific to this project

Broom handles operating system images, machine identities and licence keys. In issues, pull requests, logs and
screenshots you share:

- **No product keys, licence files or cracked / pirated software**, and no help obtaining them. Broom distributes
  only what you are licensed to use.
- **No private data from your machines or your customers.** Golden images, `bootrom.db`, and logs can contain
  passwords, keys, MAC/IP addresses and hostnames: redact them, and never attach a golden image or database.
- **Security vulnerabilities are not reported in public issues.** Use GitHub's private vulnerability reporting
  (repository → *Security* → *Report a vulnerability*) so a fix can ship before the details are known.

## Scope

This code of conduct applies in every project space — the GitHub repository (issues, pull requests, discussions,
commit messages, reviews) and any chat or forum run for Broom — and when someone represents the project in public.

## Reporting

If you experience or witness unacceptable behaviour, report it privately to the maintainer,
[@morningstar-sudo](https://github.com/morningstar-sudo), through GitHub (for example GitHub's *Report content* on
the comment or user, or a private vulnerability report if it involves a security issue). Include links or screenshots
and what happened. Reports are handled confidentially; the reporter's identity is not shared without their consent.

The maintainer will acknowledge a report as soon as reasonably possible and must not act on a report that involves
themself — in that case contact GitHub support instead.

## Enforcement

The maintainer decides what action is appropriate, guided by these steps:

1. **Correction** — for a minor or first-time breach: a private note explaining what was wrong; a public apology may
   be asked for.
2. **Warning** — for a repeated or more serious breach: a warning with consequences if it continues, and a period
   without interacting with the people involved.
3. **Temporary ban** — for a serious breach or a pattern of behaviour: no interaction with the project for a set time.
4. **Permanent ban** — for sustained harassment, threats, or sharing other people's private data or keys.

Content that breaks this code (comments, commits, issues, attachments) may be edited, hidden or removed, whether or
not further action is taken.
